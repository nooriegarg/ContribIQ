What does this issue mean?

When a user submits an empty username ("") or empty password to FastAPI's built-in OAuth2 OAuth2PasswordRequestForm, the server crashes with a confusing 500 error instead of returning a helpful 422 "Unprocessable Entity" response. Your job is to add a check that catches these empty values early and returns a clear validation error.

Files Involved
fastapi/security/oauth2.py
Add validation logic here
tests/test_security_oauth2.py
Add test cases here
What to Understand First
1
OAuth2PasswordRequestForm
Read fastapi/security/oauth2.py — this class defines the form fields. It's a Pydantic model with username and password fields.
2
Pydantic validators
Understand how @field_validator works in Pydantic v2 — this is the pattern you'll use to add the validation.
3
Existing test pattern
Look at tests/test_security_oauth2.py — there are already tests for valid credential flows you can use as your template.
Impact Map
HTTP POST /token
OAuth2PasswordRequestForm
+ field_validator (your change)
422 Validation Error
Your change intercepts the request before it reaches the route handler.
Suggested Approach
1
Open fastapi/security/oauth2.py
Find the OAuth2PasswordRequestForm class definition.
2
Add a field validator
Use Pydantic's @field_validator('username', 'password') to raise a ValueError if the value is empty after stripping whitespace.
3
Write two test cases
In tests/test_security_oauth2.py, add tests for empty username and empty password — assert the response is 422.
4
Run the full test suite
pytest tests/test_security_oauth2.py -v then the full suite to confirm nothing broke.
Pseudocode Hint
# fastapi/security/oauth2.py
# In OAuth2PasswordRequestForm:

from pydantic import field_validator

@field_validator('username', 'password')
@classmethod
def not_empty(cls, v: str) -> str:
  if not v.strip():
    raise ValueError("field must not be empty")
  return v
